worker_4 与 worker_5 在同一 step 并行跑出了**同一份结论**，这是一个有价值的信号：
不同采样路径收敛到同一机制，比单次"灵光一现"更可信。

## 7.4 轨迹的意义

- 分数曲线 `1.00 → 1.66 → 2.35 → 2.58 → 2.50` 说明**收益在早期步骤最大**（去 padding），
  后续步骤是边际优化（+5% 级别）；
- run #9 与 run #10 独立复现同一区间（差 3–4%），排除了"一次侥幸"；
- 失败的轮次并非无用：它们暴露了**框架侧**的工程问题（预算、超时、消息兼容、日志掩码），
  这些和"ASR 加速"本身同等重要——没有它们，agent 根本跑不完。

## 7.5 成本

| 项 | 量级 |
|---|---|
| CI 机时 | 约 8 小时（run #9 5.9h + run #10 5.4h，含排障轮次共约 12h） |
| 模型调用 | 每轮 6–9 个 agent 步骤，每步数十次调用；延迟 60–120 s/轮 |
| 金钱 | 框架预算 150 USD/轮（per-agent 35 USD），实际未触发上限 |

真正的瓶颈不是钱，是**单步延迟**：一个 25 分钟的 step 预算只够跑十几轮思考。
这也是 run #10 把 `max_steps` 降到 5 的原因。
